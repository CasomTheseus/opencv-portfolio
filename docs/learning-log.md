## 从 demo 到项目

原始代码是“课程笔记”风格：每个 `.cpp` 自带 `main`，整体包在 `#ifdef RUN_MAIN` 里，靠注释切换入口；路径写死；结果只 `imshow`，不落盘。

重构做了这些事：

1. **入口**：三个独立 target，各自一个 `main`，不再需要注释宏。
2. **接口**：统一 `--input / --output / --help`，不依赖当前工作目录。
3. **结果**：图片/视频 + CSV，指标可复核。
4. **数据**：`tools/make_demo_data` 生成零件阵列、标签模板/场景、合成视频，clone 即可跑。
5. **公共库**：`common/` 只放参数解析、计时、绘图、文件遍历，项目逻辑保持单文件。
6. **文档**：每个项目一份 README，写清输入输出、算法、指标和局限。

## 修掉的问题

重构时发现并修掉：

- **`ORBDetector` 构造即自毁**：构造函数里 `orb.release()` 把 ORB 指针置空，`initORB` 直接段错误（本地复现 exit 139）。
- **析构函数未实现**：头文件声明了 `~ORBDetector()`，`.cpp` 没有定义，正常使用会链接失败。
- **`matches[0]` 未判空**：匹配为空时越界。
- **绝对路径**：`/Users/.../Desktop/资料/...` 在素材搬家后全部失效，改为命令行参数。
- **阻塞式演示**：`waitKey(0)` 放在循环里，批量处理无法自动化；改为可选的 `--gui`。
- **不可复现**：依赖课程图片和视频，且部分素材含个人信息；改为合成数据。

原始练习里还有一些问题，记录在这里但不影响归档代码：

- `QuickDemo::tracking_bar_demo` 在 `LIGHTNESS SWITCH` 窗口上创建 `LIGHTNESS AND CONTRAST SWITCH` 的 trackbar，窗口名不一致。
- `showHistogram` 三条曲线都用了 `b_hist`，G/R 通道画的是蓝色数据。
- `drawing_demo` 把结果合成到 `dst`，却显示 `image`。
- `video_demo` 每帧调用 `color_space_Demo`，每帧两次 `imwrite`。
- `opencv4_006` 用 `contours.size()` 索引近似多边形的点，存在越界风险。
- HOG 滑窗里对整张图算特征，而不是当前窗口；`count == 0` 时会除零。
- `yolov4detection.cpp` 的 `image_detection;` 少了括号，函数没有被调用。
